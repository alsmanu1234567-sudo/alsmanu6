# ليش كانت صفحة التحكم (لوحة السيرفر) تأكل رام وتوقف البوت؟ — تدقيق وقياس فعلي

**الإصدار:** 8.2.0 · **التاريخ:** 2026-11-20

---

## 1) القياس الحقيقي (ليس تخميناً)

شغّلنا اللوحة فعلياً وقسنا `VmRSS` من `/proc`:

| الحالة | ذاكرة العملية |
|---|---|
| بعد الإقلاع مباشرة | **43 MB** |
| بعد 60 طلباً (تصفح/لوق/overview) | **55 MB** |
| بعد معاينة ملف 15MB (معاينة مقتطعة) | **56 MB** |

هذه **اللوحة وحدها**، ويُضاف إليها:
- **نفق عام** (cloudflared أو بديله): عادةً **25–60 MB** لكل نسخة.
- المجموع العملي لكل لوحة مفتوحة: **70–120 MB**.

على استضافة بحد ذاكرة صغير (512MB–1GB) هذا كافٍ لدفع الاستهلاك فوق الحد →
**OOM killer** يقتل البوت (لأنه أكبر مستهلك) → «البوت يوقف» بعد فتح اللوحة.

## 2) أسباب العطل (خمسة، كلها مؤكدة من الكود)

1. **عملية Node كاملة لكل لوحة.** اللوحة ليست صفحة داخل البوت، بل عملية مستقلة
   (`fork`) تعمل دائماً ما دامت الجلسة سارية.
2. **لا إغلاق بالخمول.** كانت تعيش حتى انتهاء المدة التي اخترتها — حتى **7 أيام** —
   ولو لم تفتحها مرة واحدة.
3. **نسخ يتيمة تتراكم.** لو أُغلق الرابط أو انهارت العملية، كان `cloudflared` / عملية
   اللوحة يبقى حياً بلا إغلاق، فكل محاولة فتح جديدة تضيف 70–120MB أخرى.
4. **بلا سقف ذاكرة.** لا `--max-old-space-size` ولا حد أقصى لاستهلاك اللوحة.
5. **حلقة إعادة تشغيل النفق كل 5 ثوانٍ** عند فشل النفق → عملية/اتصالات تُعاد بلا توقف
   (استهلاك معالج وذاكرة متجدد).

## 3) الإصلاحات المنفّذة

| # | الإصلاح | القيمة |
|---|---------|--------|
| 1 | **إغلاق تلقائي بالخمول** | 20 دقيقة افتراضياً، قابلة للتغيير `BOT_CONTROL_IDLE_MINUTES` |
| 2 | **سقف كومة اللوحة** | `--max-old-space-size=96` + `--max-semi-space-size=2` (`BOT_CONTROL_HEAP_MB`) |
| 3 | **إغلاق ذاتي عند تجاوز الذاكرة** | إذا تجاوزت اللوحة 200MB تُغلق نفسها (`BOT_CONTROL_MEM_MB`) |
| 4 | **نسخة واحدة فقط** | أي لوحة سابقة حية تُلغى قبل إنشاء الجديدة |
| 5 | **تنظيف الأيتام** | يتم قتل شجرة العملية (`kill -9` للمجموعة) حتى لو فشل طلب الإيقاف |
| 6 | **إيقاف النفق مع اللوحة** | `stopTunnel()` على exit/SIGTERM/SIGINT + إلغاء حلقات إعادة التشغيل |
| 7 | **فحص ذاكرة حرة قبل التشغيل** | يُرفض التشغيل إن كانت الحرة < 180MB (`BOT_CONTROL_MIN_FREE_MB`) برسالة عربية واضحة |
| 8 | **حارس ذاكرة البوت صار ذكياً** | عند ارتفاع الرام: **يوقف اللوحة أولاً** ويعيد القياس بعد 5 ثوانٍ، ولا يعيد تشغيل البوت إلا لو بقيت الذاكرة عالية |
| 9 | **شفافية في الواجهة** | صفحة «الجلسة والأمان» تعرض ذاكرة اللوحة + كم دقيقة باقية للإغلاق التلقائي |

```
✅ اللوحة أغلقت نفسها بعد الخمول
```

اختبار تنظيف الأيتام:
```
قبل: يعمل؟ true pid 23499
بعد: أُوقف؟ true · العملية اليتيمة حية؟ false · ملف الجلسة موجود؟ false
```

## 5) ماذا تفعل أنت (أفضل ممارسة)
- افتح اللوحة عند الحاجة فقط؛ **تُغلق نفسها** بعد 20 دقيقة بلا استخدام.
- استخدم زر «🔒 إيقاف الرابط» من تيليجرام عند الانتهاء بدل تركها مفتوحة.
- لو ظهرت رسالة «الذاكرة الحرة أقل من الحد»: أوقف اللوحة القديمة أو أعد تشغيل البوت.
